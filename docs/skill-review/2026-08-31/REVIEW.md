# Pulse 项目分析 Skill 评审说明

这组三个 Skill 是未发布评审稿，不会被运行时自动发现或替换生产版本。

共同认知模型是：顶层目标或项目需求 → 可独立验收的 Requirement / Workstream → 当前进展证据 → Atomic Todo。`project-progress-analysis` 负责把材料解释成事实与状态，`project-task-extractor` 只从已确认项目语境中产生原子任务，`weekly-report` 负责跨周期压缩变化、影响、风险和下一动作。写数据库、去重、删除、权限和审计仍属于 Tool / Task Service。

本次参考的内部项目进展文档只用于提炼通用行文逻辑：目标先行、分层追踪、负责人明确、进展与时间预期并列、风险依赖单列、连续周期比较。评审稿没有复制具体项目名称、指标、人员、链接或案例。

建议评审重点：Skill 的触发边界是否足够清楚；“进展、计划、结果、风险、决策”的区分是否符合你的管理习惯；Todo 原子化程度是否合适；周报结构是否适合你主要的汇报对象。批准后再通过 Skill Studio 保存为候选、运行评测并人工发布。
